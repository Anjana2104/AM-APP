# Notifications

**Module:** Notifications  
**Access:** All users (receive) | `config.admin` (configure triggers)

---

## Overview

The EAM notification system automatically alerts users when important changes happen to records — such as a SOW status changing, a resource being linked, or a bulk import completing. Notifications appear in real-time via the bell icon in the application header.

---

## Notification Bell

> **Screenshot:** Application header — bell icon with red badge showing unread count

### What You See

| Element | Description |
|---------|-------------|
| 🔔 Bell icon | Located in the top-right of the header |
| Red badge | Shows the count of unread notifications |
| No badge | All notifications have been read |

---

## Step-by-Step: Viewing Notifications

1. Look for the **bell icon** (🔔) in the top-right header area.
2. If a **red badge with a number** appears, you have unread notifications.
3. Click the bell icon.
4. A **dropdown list** opens showing recent notifications.

### Notification List Columns

| Column | Description |
|--------|-------------|
| Message | Description of what changed |
| Source | Which module/table the change came from |
| Timestamp | When the change occurred |

---

## Step-by-Step: Acting on a Notification

1. Open the notification dropdown.
2. Click on any notification row.
3. You are navigated directly to the **relevant record** (e.g., the SOW that changed, the request that was updated).
4. The notification is marked as **read** automatically.

---

## Step-by-Step: Marking All as Read

1. Open the notification dropdown.
2. Click **Mark All Read** at the top of the dropdown.
3. The red badge disappears.
4. All notifications are marked as read — they remain in the list but no longer count toward the badge.

## How Notifications Are Triggered

Notifications are generated by the server when a **monitored field changes** on a record. The rules are configured in [App Settings → App Notifications](./08-configuration.md).

### Common Trigger Examples

| Scenario | Notification Sent |
|----------|------------------|
| SOW Processing Status changes to "Completed" | Configured recipients notified |
| A resource is linked to a new SOW | Wildcard trigger fires for `ra_process` table |
| Bulk import of resources completes | `__bulk_insert__` trigger fires |
| A Client Request is marked as "Approved" | Recipients configured for that status change |

---

## Notification Message Format

Notification messages use **template tokens** that are replaced with actual values at the time of the change.

**Example template:**
```
The {field} of "{record_name}" changed from "{old_value}" to "{new_value}" by {changed_by}.
```

**Rendered example:**
```
The Processing Status of "Beeline-1234" changed from "In Review" to "Approved" by john.doe.
```

## Troubleshooting

| Issue | Solution |
|-------|---------|
| Not receiving notifications | Check that your user account is listed as a recipient in the relevant trigger (App Settings → App Notifications) |
| Bell shows no badge but changes happened | The trigger for that field may not be configured — ask your admin |
| Notification links to wrong record | The trigger may have an incorrect source table set — contact your admin |

## Admin Data Management (App Settings)

Administrators can manage notification data from **App Settings → Manage Data**:

- **Notifications History**: backup and delete notifications visible in current user scope.
- **Notification Triggers**: backup and delete configured trigger rules.

> ⚠️ Delete operations are irreversible. Always take backup before delete-all actions.

---

## Notification Snooze (User Settings)

You can configure **snooze rules** to temporarily mute specific notifications for a defined period. Only notifications that are relevant to your account (based on your role and group memberships) appear in the snooze selector.

### Step-by-Step: Adding a Snooze Rule

1. Navigate to **User Settings** from the Settings & Configuration (⚙️) menu.
2. Click the **Notification Snooze** tab.
3. Click **+ Add Rule**.
4. Select the **notification trigger** to snooze (only triggers relevant to you are shown).
5. Set a **start date** and **end date** for the snooze period.
6. Click **Save**.

During the snooze period, matching notifications are suppressed for your account only. Other users are unaffected.
